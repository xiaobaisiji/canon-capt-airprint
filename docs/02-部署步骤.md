## 3. 部署前的检查清单

```bash
# 1) 打印机是否被识别
lsusb | grep -i canon
#   期望: Bus 001 Device 023: ID 04a9:271c Canon, Inc. LBP7010C/7018C

# 2) 设备节点
ls -l /dev/usb/lp*
#   期望: crw-rw---- 1 root lp ... lp0（可能有多个，需要区分）

# 3) CUPS 是否在跑
systemctl is-active cups; lpstat -p -d

# 4) 谁在抢 USB 打印机（重要）
systemctl is-active ipp-usb      # 若 active，必须先屏蔽
fuser -v /dev/usb/lp0

# 5) 是否有 32 位运行库支持
dpkg --print-foreign-architectures   # 应含 i386
ldd /usr/bin/captmoncnacb | grep 'not found'   # 装完驱动后检查

# 6) 局域网地址
ip -4 route get 1.1.1.1 | awk '{for(i=1;i<=NF;i++) if($i=="src") print $(i+1)}'
```

> **多打印机共存提醒**：如果还接了别的打印机，`/dev/usb/lp0` 和 `lp1` 的编号会随插拔顺序变化。必须用第 5 步的 udev 规则按 VID/PID 固定设备名，否则 `ccpd` 会把 CAPT 数据发给错误的机器（表现为写操作永久阻塞）。

## 4. 部署步骤（10 步）

### 4.1 安装 CAPT 驱动

```bash
mkdir -p /opt/canon-capt && cd /opt/canon-capt
curl -# -L -o drv.tar.gz \
  https://gdlp01.c-wss.com/gds/6/0100004596/05/linux-capt-drv-v271-uken.tar.gz
tar xzf drv.tar.gz --strip-components=1

cd /opt/canon-capt/64-bit_Driver/Debian
dpkg -i --force-depends cndrvcups-common_3.21-1_amd64.deb
dpkg -i --force-depends cndrvcups-capt_2.71-1_amd64.deb
ldconfig

# 验证
ls -l /usr/lib/cups/filter/pstocapt3 /usr/sbin/ccpd /usr/sbin/ccpdadmin
ls /usr/share/cups/model/ | grep -i 7010
```

包内提供了 32 位与 64 位两套（`32-bit_Driver/` 与 `64-bit_Driver/`），x86_64 系统用 **64 位**那套。

**注意**：
- `--force-depends` 是必要的，包声明的 `libgcc1` 在新 Debian 上已被 `libgcc-s1` 取代
- `dpkg` 报依赖错误但文件已落位时不用慌，下一步检查 `pstocapt3` 是否存在

### 4.2 补 i386 运行库（**最容易漏的一步**）

64 位驱动包内部仍带着 **32 位**的助手与库：

```bash
file /usr/bin/captmoncnacb /usr/lib/libcaptfilter.so.1.0.0
#   两者都是 ELF 32-bit

dpkg --add-architecture i386
apt-get update
apt-get install -y libxml2:i386 libpopt0:i386

cat > /etc/ld.so.conf.d/zz-i386-multiarch.conf <<'EOF'
/lib/i386-linux-gnu
/usr/lib/i386-linux-gnu
EOF
ldconfig

# 必须为 0
ldd /usr/bin/captmoncnacb | grep -c 'not found'
```

不装的话 `ccpd` 会打印：

```
ccpd: DA[0]: bidiNew() Error! name=/usr/bin/captmoncnacb
```

子进程以 `127` 退出，随后所有作业卡死。

### 4.3 udev：固定设备名 + 禁止 USB 自动挂起

```bash
cat > /etc/udev/rules.d/50-canon-lbp-no-autosuspend.rules <<'EOF'
ACTION=="add", SUBSYSTEM=="usb", ATTR{idVendor}=="04a9", ATTR{idProduct}=="271c", ATTR{power/control}="on"
ACTION=="add", SUBSYSTEM=="usb", ATTR{idVendor}=="04a9", ATTR{idProduct}=="271c", TEST=="power/autosuspend_delay_ms", ATTR{power/autosuspend_delay_ms}="-1"
EOF

cat > /etc/udev/rules.d/51-canon-lbp-link.rules <<'EOF'
SUBSYSTEM=="usbmisc", KERNEL=="lp*", ATTRS{idVendor}=="04a9", ATTRS{idProduct}=="271c", SYMLINK+="usb/lbp7010c"
EOF

# 阻止 CUPS 的 usb 后端来抢
mkdir -p /usr/share/cups/usb
printf '0x04a9 0x271c no-reattach\n' > /usr/share/cups/usb/capt-printers.usb-quirks

udevadm control --reload-rules
udevadm trigger --subsystem-match=usbmisc
udevadm trigger --subsystem-match=usb
ls -l /dev/usb/lbp7010c      # 期望 -> lp0（或 lp1）
```

### 4.4 USB 复位工具

CAPT 驱动一旦在传输中途被打断，USB bulk 端点会停在 stall 状态，此时**只有设备级复位能救**（`modprobe -r usblp` 只是解绑驱动，不够）。

```bash
cat > /usr/local/sbin/canon-usbreset <<'PYEOF'
#!/usr/bin/env python3
import fcntl, glob, os, sys, time
USBDEVFS_RESET = 0x5514
VID, PID = "04a9", "271c"
found = False
for f in glob.glob('/sys/bus/usb/devices/*/idVendor'):
    d = os.path.dirname(f)
    try:
        if (open(d+'/idVendor').read().strip(), open(d+'/idProduct').read().strip()) != (VID, PID):
            continue
    except OSError:
        continue
    found = True
    node = '/dev/bus/usb/%03d/%03d' % (int(open(d+'/busnum').read()), int(open(d+'/devnum').read()))
    try:
        fd = os.open(node, os.O_RDWR)
        fcntl.ioctl(fd, USBDEVFS_RESET)
        os.close(fd)
        print('已复位', node)
    except OSError as e:
        print('复位失败', node, e, file=sys.stderr)
    time.sleep(1)
sys.exit(0 if found else 1)
PYEOF
chmod 755 /usr/local/sbin/canon-usbreset
```

### 4.5 CUPS 配置

```bash
cp -a /etc/cups/cupsd.conf /etc/cups/cupsd.conf.bak.$(date +%F)
python3 - <<'PY'
import re
p='/etc/cups/cupsd.conf'; s=open(p).read()
# 监听交给 systemd，避免重复绑定
s=re.sub(r'^[ \t]*(Listen|Port)[ \t]+.*$', lambda m:'# '+m.group(0), s, flags=re.M)
# 不自己广播，AirPrint 记录由 avahi 文件统一发布
s=re.sub(r'^BrowseLocalProtocols.*$','BrowseLocalProtocols none',s,flags=re.M)
# Host 头通配
if 'ServerAlias' not in s:
    s=re.sub(r'^(LogLevel[ \t]+.*)$', r'\1\nServerAlias *', s, count=1, flags=re.M)
# 纸张尺寸（关键：不要加引号）
s=re.sub(r'^DefaultPaperSize.*$','',s,flags=re.M)
s=re.sub(r'^ReadyPaperSizes.*$','',s,flags=re.M)
s=re.sub(r'^(ServerAlias[^\n]*)$', r'\1\nDefaultPaperSize A4\nReadyPaperSizes A4,A5,B5,Legal', s, count=1, flags=re.M)
# 放开访问控制（保留 /admin/conf、/admin/log 的认证）
def fix(m):
    tag, body = m.group(1), m.group(2)
    inner = re.sub(r'^[ \t]*(Allow|Deny)\b.*\n?','',body,flags=re.M)
    if re.search(r'^[ \t]*Order[ \t]+allow,deny[ \t]*$', inner, flags=re.M):
        inner = re.sub(r'^([ \t]*Order[ \t]+allow,deny)[ \t]*$', r'\1\n  Allow all', inner, count=1, flags=re.M)
    else:
        inner = '\n  Order allow,deny\n  Allow all\n' + inner
    return tag + inner + '</Location>'
s=re.sub(r'(<Location\s+[^>]*>)(.*?)</Location>', fix, s, flags=re.S)
open(p,'w').write(s)
PY

# 631 常驻监听（cupsd 空闲退出后由 systemd 唤醒）
mkdir -p /etc/systemd/system/cups.socket.d
cat > /etc/systemd/system/cups.socket.d/10-lan-631.conf <<'EOF'
[Socket]
ListenStream=
ListenStream=/run/cups/cups.sock
ListenStream=631
EOF
systemctl daemon-reload && systemctl stop cups && systemctl restart cups.socket && systemctl start cups
ss -ltn | grep ':631'     # 期望 *:631
```

**为什么把 `Listen` 交给 `cups.socket`**：Debian 的 cupsd 以 `-l`（launchd 模式）运行，如果 `cupsd.conf` 里也写 `Listen`，会与 systemd 的 socket 抢同一端口。交给 socket 的另一个好处是：cupsd 因 `IdleExitTimeout` 退出后，631 端口依然在，客户端一来就被唤醒。

### 4.6 创建队列

```bash
lpadmin -p LBP7010C -E \
  -v ccp://localhost:59687 \
  -P /usr/share/cups/model/CNCUPSLBP7010CCAPTJ.ppd \
  -D "Canon LBP7010C" -L "USB (/dev/usb/lp0)" \
  -o printer-is-shared=true -o PageSize=A4
cupsaccept LBP7010C; cupsenable LBP7010C
```

端口固定用 **59687**（Canon 官方文档值，`ccpd` 的数据端口；59787 是状态/UI 端口）。

### 4.7 ccpd 的 systemd 单元（三处关键）

```bash
cat > /etc/systemd/system/ccpd.service <<'EOF'
[Unit]
Description=Canon CAPT Printer Daemon (ccpd)
After=network-online.target cups.service
Wants=network-online.target

[Service]
Type=forking
ExecStart=/usr/sbin/ccpd
Restart=on-failure
RestartSec=3
KillMode=control-group
TimeoutStopSec=5

[Install]
WantedBy=multi-user.target
EOF

mkdir -p /etc/systemd/system/ccpd.service.d

# ① locale —— 没有它 captmoncnacb 必崩
cat > /etc/systemd/system/ccpd.service.d/20-locale.conf <<'EOF'
[Service]
Environment=LANG=en_US.UTF-8
Environment=LC_ALL=en_US.UTF-8
Environment=HOME=/root
EOF

# ② 启动前清理 + USB 复位
cat > /etc/systemd/system/ccpd.service.d/40-preflight.conf <<'EOF'
[Service]
ExecStartPre=-/usr/bin/pkill -9 -x captmoncnacb
ExecStartPre=-/usr/local/sbin/canon-usbreset
ExecStartPre=/bin/sleep 2
EOF

systemctl daemon-reload
# enable 会被 update-rc.d 拦（Canon 的 init 脚本没有 runlevel），直接建 wants
mkdir -p /etc/systemd/system/multi-user.target.wants
ln -sf /etc/systemd/system/ccpd.service /etc/systemd/system/multi-user.target.wants/ccpd.service

ccpdadmin -p LBP7010C -o /dev/usb/lbp7010c
systemctl restart ccpd
```

**三个必须记住的点**：

1. **`Type=forking`**：`ccpd` 自己会 fork 到后台。写成 `Type=simple` 时 systemd 认为主进程已退出，会按 `KillMode=control-group` **把整个 cgroup（含刚 fork 出来的守护进程）杀掉**，日志表现为重启计数器一路涨（实测到 399 次）。
2. **`LANG`/`LC_ALL`**：`captmoncnacb` 按 locale 去 `/usr/share/captemon/msgtablecnacb.xml` 查状态消息，而这个表只有 `locale="en"` 条目。服务环境无 `LANG` 时查不到 → 返回 NULL → `strcmp(NULL)` → `segfault at 0`（`dmesg` 里 `f3 a6` 即 `repz cmpsb`）。助手一崩，`ccpd` 永久 BUSY。
3. **`ExecStartPre` 清理 + 复位**：上一个助手被强杀后会占着 `/dev/usb/lp0` 不放，新助手打不开设备，表现为“重启完第一单必卡”。

### 4.8 发布 AirPrint

```bash
cat > /etc/avahi/services/canon-airprint.service <<'EOF'
<?xml version="1.0" standalone='no'?><!--*-nxml-*-->
<!DOCTYPE service-group SYSTEM "avahi-service.dtd">
<service-group>
  <name replace-wildcards="yes">Canon LBP7010C (%h)</name>
  <service>
    <type>_ipp._tcp</type>
    <subtype>_universal._sub._ipp._tcp</subtype>
    <port>631</port>
    <txt-record>txtvers=1</txt-record>
    <txt-record>qtotal=1</txt-record>
    <txt-record>rp=printers/LBP7010C</txt-record>
    <txt-record>ty=Canon LBP7010C</txt-record>
    <txt-record>note=fnOS</txt-record>
    <txt-record>pdl=image/urf,application/pdf,image/jpeg,image/png</txt-record>
    <txt-record>URF=W8,SRGB24,CP255,RS600,DM1</txt-record>
    <txt-record>Color=T</txt-record>
    <txt-record>Duplex=F</txt-record>
    <txt-record>product=(Canon LBP7010C)</txt-record>
    <txt-record>priority=50</txt-record>
    <txt-record>Transparent=F</txt-record>
    <txt-record>Binary=F</txt-record>
    <txt-record>TBCP=F</txt-record>
  </service>
</service-group>
EOF
systemctl restart avahi-daemon
avahi-browse -rt _ipp._tcp | grep -A5 LBP7010C
```

**这份 TXT 是实测能让 iOS 15 和 iOS 26 都发现的关键**，几个反直觉的细节：

| 字段 | 错误写法 | 正确写法 | 后果 |
|---|---|---|---|
| `URF` | `none` | `W8,SRGB24,CP255,RS600,DM1` | `none` 等于声明“不是 AirPrint 打印机”，iOS 26 直接忽略整条记录 |
| `pdl` | `application/pdf` 开头 | `image/urf` 放首位 | 老版 iOS 能认，iOS 26 不认 |
| `adminurl` | `http://%h:631/...` | **删掉** | avahi 只替换服务名里的 `%h`，TXT 里的 `%h` 会原样输出，成为非法 URL |
| `usb_MFG`/`usb_MDL`/`kind`/`mopria-certified` | 带上 | **删掉** | 某些 iOS 版本对多余字段敏感 |

> 调试技巧：iOS 打印面板不显示打印机时，先在 NAS 上 `tcpdump -i any -n -A 'udp port 5353 or tcp port 631'`，让用户打开打印面板。若抓不到任何 `_ipp` 查询，说明 iOS 在浏览阶段就把这台机器过滤掉了，要回去改 TXT。

### 4.9 屏蔽 ipp-usb

```bash
systemctl disable --now ipp-usb
systemctl mask ipp-usb
```

`ipp-usb` 会用 libusb 接管 USB 打印机、踢掉内核的 `usblp`，与 `ccpd` 抢同一个接口。`dmesg` 里的典型证据：

```
usblp1: removed
usb 1-8: reset high-speed USB device number 26 using xhci_hcd
usblp 1-8:1.0: usblp1: USB Bidirectional printer dev 26 ...
```

（反复 removed/re-add 就是两个驱动在抢设备。）

> 代价：其他支持 IPP-over-USB 的打印机（如 HP Laser 108a）不再免驱被发现，需要单独建队列。

## 5. 一键脚本

把上面 10 步合并成一个幂等脚本（可重复执行）：

```bash
sudo bash canon-capt-airprint-setup.sh
```

脚本头部有三个变量需要按机型改：

```bash
QUEUE="LBP7010C"                  # 队列名
USB_PID="271c"                    # 打印机的 USB PID
PPD_NAME="CNCUPSLBP7010CCAPTJ.ppd" # 驱动包内对应 PPD
```

常用机型对照（同一个驱动包内）：

| 机型 | PPD |
|---|---|
| LBP7010C | `CNCUPSLBP7010CCAPTJ.ppd` |
| LBP7018C | `CNCUPSLBP7018CCAPTK.ppd` |
| LBP2900 | `CNCUPSLBP2900CAPTK.ppd` |
| LBP3000 | `CNCUPSLBP3000CAPTK.ppd` |
| LBP5100 | `CNCUPSLBP5100CAPTK.ppd` |
| LBP6300 | `CNCUPSLBP6300CAPTK.ppd` |

完整 PPD 列表：`ls /usr/share/cups/model/ | grep CNCUPS`
